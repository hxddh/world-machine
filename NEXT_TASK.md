# Next Coding Task — M219 Long-lived Pi Analyst RPC Session

M214–M218 now provide a complete read-only evidence tool path from `world-query` through a local archive-bound stdio host and into Pi as dynamically registered analyst tools. The next missing layer is a reusable repository-side controller that can keep the restricted Pi analyst process alive, submit analyst prompts, and return completed analyst turns without reusing the decision-only `world-pi-rpc` semantics.

## Current baseline

- M214 defines the version-1 read-only analyst host protocol.
- M215 binds a fixed left/right archive pair to a long-lived JSONL tool process.
- M216 removes duplicate CLI comparison authority.
- M217 adds a provider-neutral, correlated stdio client/session for the analyst host.
- M218 adds the restricted Pi extension and launcher: Pi receives only catalog-derived read-only World Machine tools, while archive paths remain process configuration and `world-pi-rpc` remains dedicated to in-World `AgentRuntime` decisions.

## M219 — long-lived Pi analyst RPC controller/session

Add a provider-specific Pi analyst session above M218 that:

- starts one restricted Pi RPC process for an analyst session and keeps it alive across prompts;
- remains single-flight: at most one analyst prompt is outstanding because Pi's asynchronous event stream is session-ordered rather than request-multiplexed;
- sends explicit prompt request IDs and validates the immediate prompt acknowledgement;
- consumes Pi's asynchronous event stream through the complete analyst turn, including tool-execution events generated by the M218 extension;
- treats the session-level settled event as the completion boundary so retries, compaction, or queued continuation cannot truncate a turn at the first low-level run boundary;
- returns the final assistant text plus structured read-only tool-call telemetry useful to higher-level analyst UX or tests;
- preserves Pi tool failures distinctly from transport/protocol failures;
- provides deterministic shutdown/timeout handling and terminates child processes on failure or drop.

Prefer a separate analyst-facing module/crate rather than extending the decision parser in `world-pi-rpc`. Shared low-level Pi RPC wire helpers may be extracted only if doing so reduces duplication without merging the two authority models.

## Boundary rules

The M219 controller is external analyst orchestration only. It must not depend on `world-agent`, `world-core`, `world-projection`, GPUI, or mutation APIs. It must not parse analyst output into `WORLD_ACTION`, invoke `AgentRuntime`, expose arbitrary filesystem paths as tools, or re-enable Pi built-in tools/resources. The only World access continues through the M218 read-only extension -> M215 archive-bound analyst host.

`world-pi-rpc` remains decision-only: tool execution there stays forbidden. M219 explicitly accepts/observes Pi tool events because those tools are the restricted analyst tools established by M218.

## Validation

- protocol parser tests for prompt acknowledgement, message/tool event accumulation, tool failure, and settled completion;
- fake-process integration tests proving two sequential prompts reuse one Pi process;
- timeout/EOF/non-zero-exit/shutdown tests with no orphaned child;
- authority tests preventing World/Projection/mutation/provider-network creep;
- existing M214–M218 tool/extension tests stay unchanged and green;
- full workspace Clippy/tests and external Pack conformance.

## Non-goals

No concurrent/multiplexed prompts, no MCP/HTTP/WebSocket server, no mutation tools, no AgentRuntime query injection, no generic provider abstraction, no UI work, and no analyst protocol v2.
